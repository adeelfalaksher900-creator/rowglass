## The baseline problem and positioning correction

Requiring an already correct replacement query merely to obtain that same repair is weak product value. A stronger case is preserving behavior during a refactor, optimization attempt or agent rewrite: the developer owns a known baseline and wants to discover where the proposed change diverges. The model helps explain and repair the proposed change; independent tests decide only agreement on the supplied fixtures.

If behavior intentionally changes, the baseline is insufficient. An updated contract and expectations need human review. This limitation must appear in onboarding and import instructions. The product should help reviewers understand and reproduce a difference, not imply an oracle has established intent automatically.

## Evaluation decisions

Freeze 24 proposed changes across six schemas. Include independently checked wrong mutations and equivalent rewrites. Separate repair-visible fixtures from final held-out fixtures; no gold SQL or held-out rows enter prompts or feedback. Model-generated challenges use a separate denominator. Preserve all attempts and failures.

Measure held-out repair, mis-repair, net repair, false acceptance, mutation detection, witness validity, original/reduced rows, deletion checks, timeout/invalid output events, calls and actual returned usage/latency. A small live subset must be labeled as such. Offline controls and mocked provider tests are never model quality results. Independent user studies are still needed to validate setup effort and reviewer comprehension.

## Optional integration selection

Tavily's [credits](https://docs.tavily.com/documentation/api-credits) and [search reference](https://docs.tavily.com/documentation/api-reference/endpoint/search) describe a free monthly allowance and domain filtering. A useful integration retrieves cited official SQLite explanations for generic concepts without leaking uploaded SQL or data. Verify actual free-account activation before runtime use; never enable paid usage implicitly.

Serverless Jobs would help resumable batch evaluation if approved AI Cloud credits become available. Supabase is justified by a durable hosted allowance ledger or shared records, not by local SQLite tests. Existing private hosting can remain during review. A public judge deployment needs independently verified access and limits.

## Current evidence versus release gaps

The existing three curated reference suites and nine wrong-repair controls are useful regression evidence. PR1 adds six tests for file safety, large review verification, non-finite results and malformed provider metadata; its 54-test GitHub run passed and an independent review found no merge blocker. A separate integer-precision gap was found during source review and is now an explicit release criterion.

Still missing: actual model runtime evidence, current deployed corrections, replayable browser/CLI evidence, held-out evaluation, complete current UI audit, judge-ready access and final media. Design or source improvements do not remove these gates. No final submission or winning claim is justified yet.
