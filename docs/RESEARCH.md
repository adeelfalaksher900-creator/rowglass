# Research and project decision

Reviewed 16 October 2026. This records design decisions, not a claim that Rowglass reproduces an academic benchmark.

## Track choice
Coding and Agentic Engineering fits a system that writes, executes and tests SQL code. Reliable current per-track submission totals were not available. We did not choose a track based on an invented low-competition estimate. Physical AI was considered, but demonstrating a focused developer workflow and independent evaluation is a better fit for the available tools and time.

## Prior competition evidence
Nebius's official [Serverless AI Builders Challenge winners](https://nebius.com/blog/posts/serverless-ai-builders-challenge-winners) describe entries built around specific problems and reproducible measurements, including model evaluation and agent fault injection. Our inference: small executable evidence and honest limits are more useful to this project than a broad chat surface. Those results do not predict this hackathon's winners. Rowglass is new work and does not reuse the winning projects' code.

## Academic evidence and changes adopted

| Primary source | Relevant method or limitation | Application in Rowglass |
|---|---|---|
| Zhong, Yu and Klein, [Semantic Evaluation for Text-to-SQL with Distilled Test Suites](https://aclanthology.org/2020.emnlp-main.29.pdf), EMNLP 2020, sections 2–4 | One database can hide semantic differences. Tests should distinguish nearby incorrect queries while preserving types and foreign keys. The paper also documents metric adaptations. | Compare outputs on several valid databases; include plausible wrong repairs as controls; preserve duplicate counts; document our exact comparison contract. We use authored fixtures, not their distilled-suite algorithm or dataset. |
| Liu et al., [Is Your Code Generated by ChatGPT Really Correct?](https://arxiv.org/pdf/2305.01210), NeurIPS 2023 | Functional tests and expanded inputs expose errors missed by smaller suites. Model-produced code needs executable evaluation. | Independent reference queries supply expected results. The model does not grade its own repair. These three SQL examples are not EvalPlus. |
| Lei et al., [Spider 2.0](https://arxiv.org/pdf/2411.07763), ICLR 2025; [official project](https://spider2-sql.github.io/) | Real SQL workflows involve large metadata, multiple dialects and several execution steps. | Keep the prototype SQLite-only and explicitly scoped. Do not imply enterprise-scale coverage, a Spider score or general SQL competence from three cases. |

The reduction feature is a simple deterministic row-deletion procedure implemented here. A final witness has no removable single row preserving a valid value mismatch. That is deliberately weaker than a global minimum or a formal equivalence result.
